# content/ — the game as data

*Last updated 2026-10-26 · rev. 2 (Claude, after the independent review; from `docs/03-GAME-DESIGN.md` rev. 2 and the owning files it names). Every number in an example is a tuning starting point.*

**Content is data.** Every class, species, skill, item, affix, set, monster, elite affix, dungeon, encounter, pet, chest, loot table, contract and status is one JSON file validated against a JSON Schema (draft 2020-12) by the Node linter (`npm run lint`, ajv) and loaded by the deterministic TypeScript sim. The schemas are the contract between the rulebook and the code: if an owning doc (the ownership table at the top of `03`) can say it, a schema can express it; if a schema cannot express it, the doc has not decided it yet. **The schema set grows as content needs it** (D-020 as amended: "the schemas in `content/schemas/`, added as content kinds need them, each with an example and linter rules") — rev. 2 added `elite-affix`, `contract`, `item-set` and `loot-table`; Phase 1 added `tuning` (the shape of `tuning.json`) and shipped the first real content, `statuses/` and `tuning.json`.

## Layout

```
content/
  schemas/                       one JSON Schema per content kind, $id https://gloamvault.dev/schemas/<kind>.schema.json
    common.schema.json             shared $defs: id pattern, every closed enum, the effect DSL, requirement, reward, tuningNumber
    class.schema.json              species.schema.json      skill.schema.json        item.schema.json       affix.schema.json
    item-set.schema.json           monster.schema.json      elite-affix.schema.json  dungeon.schema.json    encounter.schema.json
    pet.schema.json                chest.schema.json        loot-table.schema.json   contract.schema.json   status.schema.json
    hero.schema.json               (the save-side hero, not content)
    tuning.schema.json             the shape of tuning.json: sections of tuningNumber leaves (added in Phase 1, D-049)
  examples/                      one valid example per schema, <kind>.example.json (a variant: <kind>-<variant>.example.json)
  classes/<id>.json
  species/<id>.json
  skills/<class>/<id>.json       <class> is the skill's classId: warden/, blade/, …, and field/, pet/, monster/
  items/<kind>/<id>.json         <kind> is the item's `kind` value, spelled exactly: weapon/, armor/, shield/, focus/, ring/,
                                 talisman/, relic/, consumable/, material/, stone/, tome/, key/, ammo/, egg/, treat/
  affixes/<id>.json
  sets/<id>.json
  monsters/<id>.json
  elite-affixes/<id>.json
  dungeons/<dungeon>/dungeon.json  zones, floors, the generator, curios, traps, secrets, Pacts, presets
  dungeons/<dungeon>/templates/<id>.json
  encounters/<id>.json
  pets/<id>.json
  chests/<id>.json
  loot-tables/<id>.json
  contracts/<id>.json
  statuses/<id>.json
  tuning.json                    the balance runner's tables of tuningNumber (R per band, baselines, curves)
```

- **One file per record**, named by its `id`: `content/<kind>/<id>.json`, with skills under their class folder, items under their kind folder, and a dungeon's room templates beside its `dungeon.json` (each template file validates against `dungeon.schema.json#/$defs/template` and is merged into `templates[]` by the loader). The file name must equal the `id` inside it.
- **Ids are kebab-case** (`^[a-z0-9]+(-[a-z0-9]+)*$`) and unique within their kind. Skills are prefixed with their class (`warden-shield-slam`); pet actives with `pet-`; sub-ids inside a record (schools, attacks, traits, choices) only need to be unique within that record.
- **Properties are camelCase.** Closed sets are enums in `common.schema.json`; nothing else in a schema repeats them. Numbers are integers wherever the sim is integer-only (percent points, stat points, energy, gold, XP); multipliers on an Attack or a baseline are decimals; prices and stakes in R are decimals.
- **Every object is `additionalProperties: false`.** A typo is a lint error, not a silently ignored field.
- **Cross-file references** are plain ids (`classId`, `skillId`, `monsterId`, `affixId`, `setId`, `tableId`, reward and requirement `id`s …). The schema checks the shape; the linter checks the target exists.
- `hero.schema.json` describes a **save record**, not content. It reuses `item.schema.json#/$defs/itemInstance` and `pet.schema.json#/$defs/petInstance`; the loader migrates by `saveVersion`.
- **Deferred records** end in `.json.later` (Phase 7 shipped the last of them: the Crypts and Vault templates, Keeper's Peace and Tide-turner): the loader and the linter ignore them, so a record that references content from a later phase can wait beside the shipped one without dangling (D-072, D-076). Renaming it to `.json` ships it.
- **Generators**: the six classes and their skills (`tools/content/gen-class-<class>.ts`) and every item (F–S since Phase 7; the Skill Tome under `items/tome/` excepted), affix, set, named unique and loot table (`tools/content/gen-items.ts`) and the wayfarers (`tools/content/gen-wayfarers.ts`) are written by re-runnable scripts; a sheet or table change is a re-run, never a hand edit of that JSON (CLAUDE.md "re-runnable builds"). The species, pets, monsters, dungeon, encounters, chests and contracts are hand-kept JSON.

## The effect DSL

Skills, monster attacks, statuses, traits, elite affixes, set bonuses, curios, traps, relics and consumables all describe what they do as a list of `effect` lines (`common.schema.json#/$defs/effect`), resolved in order:

| kind | required fields | meaning |
|---|---|---|
| `damage` | `multiplier`, `damageType` | Attack × multiplier through the §2.2 damage formula |
| `heal` / `shield` | one of `multiplier`, `percent`, `amount` | heal or absorb |
| `applyStatus` / `removeStatus` | `status` (+ `chance`, `duration`) | a status from the standard set |
| `buffStat` / `debuffStat` | `stat` + `amount` or `percent` | move a derived stat for `duration` turns |
| `momentum` / `light` | `amount` | move the Momentum bar or the light dial |
| `pool` | `amount` or `percent` | restore or drain stamina/mana |
| `timeline` | `energy` | push (negative) or pull the accumulator |
| `rowSwap`, `taunt`, `dispel` | — | act on `target` |
| `summon` | `summonId` | add a monster to the acting side |
| `revive` | `percent` | revive a downed ally at that HP |
| `loot` | `amount` or `percent` | gold or drop-odds change |
| `custom` | `customId`, optionally `itemId` | a hand-written sim hook, named so the linter can list them; `itemId` names the item or material the hook grants or consumes (rule 2 resolves it) |

`target` on a line overrides the owner's target; `scalesWith` names the attribute whose points above 10 add to the line; `note` is for the designer and ignored by the sim. The `target` enum covers rows on both sides (`partyFront`, `partyBack`, `allyRow`, `enemyRow`, `enemyRowBack`), `enemyRandom`, `summon`, `downedAlly`/`allDowned` (within the revive window) and `fallenAlly` (past it); "single + behind" is two lines, `enemy` then `enemyRowBack`.

Two more shared shapes live beside it. A **`requirement`** (`{kind, id?, min?, amount?, consumed?}`, kinds `item · fieldSkillRank · attribute · detection · gold · light · classId · speciesId`) gates a curio choice, a door or a kit; a list is an AND. A **`reward`** (`{kind, id?, amount?, chance?, grade?, tier?, difficultyMin?}`, kinds `item · material · tome · shard · gold · luck · title · waystone`) is one drop line on a boss, a trap disarm or a contract; chest keys are items.

## What the linter checks that the schema cannot

`npm run lint` runs ajv on every file, then these cross-file rules. Each failure prints `<file>: <rule>` and the run exits 1.

**Ids and references**
1. The file name equals the record's `id`; ids are unique within a kind; a skill sits in the folder of its `classId`, an item in the folder of its `kind`, a template under its dungeon.
2. Every reference resolves: `classId`, `speciesId`, `skillId`, `prerequisiteId`, `ultimateSkillId`, `starterSkillIds`, `starterKit`, `monsterTechniqueIds`, `monsterTechniqueSkillIds`, `innateSkillId`, `itemId`, `affixId`, `setId`, `pieces`, `safeItemId`, `materialId`, `monsterId`, `summonId`, `familyId`, `dungeonId`, `zoneId`, `hunterId`, `bossIds`/`bossId`, `bossFirstKill`, `encounterTableIds` ↔ `tableId`, `petId`, `speciesFamilyId`, `upgradesTo`, `bossBecomes`, `trapId`, `chestId`, `elitePool` ids, **every reward `id`** (an item, material, skill, title or zone by its `kind`) and **every requirement `id`** (an item, class or species id, or a fieldSkill/attribute name by its `kind`), and a skill's `school` against its class's `schools[].id`. A `familyId` resolves when at least one monster carries it; a title resolves when some reward line or hero carries it.
3. A status file's `id` is one of the `status` enum and every enum value has a file (`content/statuses/` holds all 27).

**Classes and skills**
4. Every class has exactly **3 non-Ultimate skills per school in each of the five tiers** (3 schools × 5 tiers × 3 = the 45 of `04`; the Ultimate is the 46th, `03` §7.1). Phase 7 wrote Tiers IV–V, so every tier is required (Tier V is present but locked until Segment 3, D-099; D-070 had IV–V warn until then). A class with no skills yet (the Beast Tamer before Phase 11) is skipped.
5. Each Tier II–V skill's `prerequisiteId` is a Tier N−1 skill of the **same class and school**; Tier I skills have `null`.
6. Exactly **one** skill per class has `isUltimate: true`, it is at **Tier III**, and it is the class's `ultimateSkillId`.
7. `starterSkillIds` are three Tier I skills of that class, and so are every `starterKitOptions[].starterSkillIds` (D-099's second kits); a kit's id is unique in its class and its items resolve. **Monster techniques:** every id in a class's `monsterTechniqueIds` is a skill file of that class at **Tier III or IV** with a non-null `monsterTechniqueOf`; that monster's `monsterTechniqueSkillIds` contains the skill; and every id in any monster's `monsterTechniqueSkillIds` points back the same way (a monster may teach several classes). A skill's `monsterTechniqueMoveIds` needs a `monsterTechniqueOf` and names attacks of that monster. A technique whose monster is not in the content yet carries `monsterTechniqueLater` (and `monsterTechniqueOf: null`); once that monster exists it must be linked. **Each class that has Tier IV has exactly `techniques.perClass` (2) techniques, linked or later** (`06` §8.8: "Each class has exactly two monster techniques"). Fewer than two met in one dungeon is a **warning** that names the later ones — by D-099 the Mender meets one in Gravehollow (Troll's Regrowth waits for the Fungal Deep) and most classes meet none in Dungeon 2.
8. A class's `attributeMods` sum to **+4**; a species' net to **+2**.
9. Field skills (`classId: "field"`) exist for all eight `fieldSkill` values and no more; pet actives (`classId: "pet"`) are only referenced from `pet.actives`.

**Monsters, elite affixes, dungeons, encounters**
10. Every monster family has **all five roles** (fodder, elite, special, monster, boss) across its monsters; every zone's `hunterId` (when not null) is a monster with `role: hunter` and **every id in `bossIds` exists** and is a monster with `role: boss` and `zoneId` of that zone.
11. A boss's phases are in descending `atHpPercent` starting at 100; every phase `attacks[]` id and every behavior `then` that is not `flee`/`guard`/`swap row` is one of the monster's `attacks[].id`; a zone boss has 2 phases, a final boss 3 — "final" meaning the boss of the last floor of a dungeon with all three zones written (a partial dungeon's last boss is a zone boss and warns; D-072); each `adds[].monsterId` exists. Every reward line in `everyKill`/`firstKill` resolves (rule 2); a God item appears only as a chance line with `chance ≤ 4`.
12. `generator.roomWeights` sum to **100** over the rolled kinds; `bossFarthest` is true; `minRooms ≤ maxRooms` and every floor's `roomsMin/Max` sit inside them.
13. Floors are numbered 1..n without gaps, each inside its zone's `floors` range; zones tile the dungeon's floors; every zone's `bossIds` each appear as exactly one floor's `bossId` inside the zone, in order, the last on the zone's last floor; a floor with a `bossId` has `hunterClock: null` and the floor before it has `merchant: true`; a zone with `hunterId: null` has `hunterClock: null` on every floor.
14. `eliteAffixCount` follows the band (1 on floors 1–2, 2 on 3–6, 3 on 7+; dungeons 2–4 one higher); every `elitePool` id resolves to a `content/elite-affixes/` file whose `floorMin` ≤ the monster's lowest floor; a monster's pool holds at most one `defensive` and one `control` affix beyond the count the sim will draw; a boss, hunter or Monster-role template has an empty `elitePool`. Exactly **12** elite affixes exist.
15. Every id in a floor's `encounterTableIds` is carried by at least one encounter whose `floorBand` covers that floor and whose `dungeonId` matches; a composition totals 2–6 monsters with at most 2 Specials and 1 Monster; each monster's `row` is one of its `rows`.
16. Each curio choice's `outcomes[].chance` sum to **100** (or the list is empty); a curio with a `safeItemId` has exactly one choice whose `requires` is that single item; a `requires` line of kind `fieldSkillRank`/`attribute` names a real field skill/attribute (the schema does this), of kind `classId`/`speciesId` a real class/species. A trap's `difficulty` lies within some floor's `trapBand` of that dungeon, its `revealedBy.detection` ≤ its `difficulty`, and its `disarmReward` lines resolve.
17. A template's `doors[].offset` is inside its footprint on that side; `kinds` contains at least one rolled kind or one fixed kind; `triBudget ≤ 30000` and `drawCallBudget ≤ 60` (`07` §2.2). A dungeon's loot tables tile its floors by `floorBand`; `bossFirstKill` names the boss on the band's last floor.
18. Presets: `hard` and `dread` (named Nightmare until checkpoint 1, D-095) set every knob `normal` sets; a Pact's `weight` is 1–3 and the 12 launch Pacts exist on the first dungeon.

**Items, affixes, sets, chests, loot tables**
19. `affixSlots` matches the grade (F 0 · E 1 · D 1 · C 2 · B 2 · A 3 · S 3 · SS 4 · God 4) and `maxPlusN` the grade (F 3 · E 4 · D 5 · C 6 · B 7 · A 8 · S 9 · SS 10 · God 10).
20. `affixes.length ≤ affixSlots`; each rolled `value` lies within the affix line whose band covers the item's grade; the affix lists the item's `slot`; a set piece spends one slot on its set line.
21. `durability ≤ maxDurability`.
22. `materialRung` equals the grade's index on the ladder (F 0 … God 8) and is null exactly when `materialLadder` is null; across items that share a `visual.meshId`, `baseStats` scale by the grade multipliers (F 1.00 · E 1.35 · D 1.80 · C 2.45 · B 3.30 · A 4.45 · S 6.00 · SS 8.10 · God 11.0) relative to the F piece, rounded to integers; a line equal to the F piece's is a **flat** line and passes (percentages and penalties do not ride the ladder, `08`), and a shield's `block` may step +`equipment.shields.blockStepPerGrade` pp per grade (`08` §2.3; D-072); an armor piece's percentage secondary (Resistance, Dodge, Crit, Accuracy) may step +`items.armorPercentStep.pp` per grade above `items.armorPercentStep.fromGrade` (B) (`08` §2; Phase 7).
23. God items are `unique: true` with a `uniquePower`, one per slot, and **never appear in any random table**: no chest `table` gives God above 0, no loot table's `gradeShape` reaches God from its centre, no encounter or curio `loot` names a God item; a boss's `everyKill` may name one only as a chance line (rule 11).
24. An affix's `lines[]` bands do not overlap and run in ladder order.
25. A set's `pieces` all exist, carry its `setId`, sit in the five armor slots of its `family` (or the two ring slots of a `ringPair`), and share the set's `classIds` lock; `gradeMin ≤ gradeMax` when both are set.
26. Each chest `oddsByBand[].table` sums to **100** and contains no grade below `centreGrade`; a Grand **gear or egg** chest's table is `08` §10's shape **+1 45 · +2 35 · +3 15 · +4 5** with any God share folded into SS (crates and tomes carry no shape; D-072); `pity.plusOneWithin < plusTwoWithin`.
27. **A loot table's `gradeShape` sums to 100** (`centre + minus1 + plus1 + plus2 + plus3`); `minus1` is 0 when the centre is F (the fold goes into `centre`); `partChance` matches `equipment.parts` (35 / 4) and `itemChance` the band row of `08` §11 for its centre grade (`tuning.json → items.lootItemChanceByCentre`: F 35 · E 40 · D 45 · C 50).

**Pets and heroes**
28. **Pet actives by grade:** a species lists 1–3 actives in unlock order; a hatched pet may use the first *N* for its grade — **F–C 1, B–A 2, S+ 3** — so a species lists at least as many as `gradeBand.max` allows and never more than 3 (a species whose band reaches S needs a third). The first unlocks at **5**, the second at **15**; all resolve to skills with `classId: "pet"`. `gradeBand.min ≤ max` and both ≤ A for a `creationChoice` pet (creation offers F eggs).
29. **Loadout presets by species:** a hero's `loadoutPresets.length` ≤ its species' `loadoutPresets` rule (default 2; Humans 3; the schema's ceiling is 4). `naturalArmor` is non-null exactly when the species sets `naturalArmorBase`; `freePointsSpent` ≤ 6 and `creationValues` = 10 + species + class + the free points; a hero's `look` names a skin tone and a face preset its species has (as rule 34).
30. A hero record (only checked in `npm run lint -- --saves`): skills' `classId` matches the hero's class or is `field`; loadout ids are known skills of the right `type`; equipped items' `slot` matches the equipment key and `classLock` allows the class; `ring` holds ring items; `level` ≤ the level its total skill ranks allow; `titles` resolve to title ids some reward line grants.

**Custom hooks and tuning**
31. Every `customId` used in any effect line anywhere in the content has a handler file `sim/src/skills/custom/<customId>.ts` (`09` §6; the handler contract is `sim/src/skills/custom/README.md`); checked once that folder exists (Phase 2 creates it).
32. `content/tuning.json` validates against `tuning.schema.json`: every section carries its `source`; every leaf is a number, a `{value, note}` pair (a non-empty `note` and nothing else), a boolean, a string of at most 240 characters or null; an object with a `value` key is always read as such a pair, never as a table.
33. Each dungeon's `secrets[]` (07 §2.6) have unique ids, a `zoneId` that is one of the dungeon's zones or null, reward ids that resolve, and each grants something (rewards, a chest, a blessing with effect lines, a shortcut, a map reveal or light); an item reward names an id or a grade.

**Skill Tomes, the Tier IV–V limits and the monster-only skills** (Phase 7, pass A, `tools/lint/rules-a.ts`)
35. **Skill Tomes** (`03` §7.5, `08` §4, §10.2): `tuning.json` → `skills.tomes.itemId` names an item of kind `tome`; a `tome` item has no slot, no consumable block and no `classLock` (it is read in town; the skill on the instance, `skillId`, names the class); every reward line of kind `tome` anywhere (a boss's first kill, a secret, a curio) names a class skill a Tome may carry — not a field, pet or monster skill, not a monster technique (linked or later: learned only by witnessing), not above `skills.obtainableTierMax` (Tier V is locked, D-099) — or a `tier` within 1 … that maximum; a Skill Tome chest's `tomeTiers` (its own, else `economy.chests.tomeTiers`) sits inside the same range; with `--saves`, a Tome in a hero's bag names such a skill.
36. **The D-099 Tier IV–V limits** (`tuning.json` → `skills.limits`): no `execute-multiplier` or `execute-multiplier-below-hp` line anywhere carries a `multiplier` above `executeMaxMultiplier` (6.0); every custom line with an `amount` in a skill `perFloor` names (Undying Rage 1, Deathless 2) or `perCast` names (Oath of the Vault 1) carries exactly that count, its Mastery included; a skill `ambushCutMaxPercent` names (Never Lost 30) carries a `party-ambush-modifier` line that never cuts past the cap; every skill the limits name exists.
37. **A monster-only skill is used**: a skill of `classId: "monster"` is named somewhere in some monster record.

**Floors, encounters, behaviour, curios and traps** (Phase 7, `tools/lint/rules-c1.ts`)
45. **Floors and zones** (`07` §1.1, §2.3, §2.10): the first zone's `waystone` is true (its stone is lit from the start); `monsterLevel` never falls from floor to floor and the first and last floors' levels are `levelRange.min` and `.max`; the last floor of a three-zone dungeon that carries a boss is the throne — exactly 4 rooms, no secret, no merchant (G3); each zone's templates wear its kit's prefix (`cel-`, `cry-`, `vlt-`) and between them host every room kind its floors need (entry, fight, rest, stairs where a floor has none of a boss, boss, merchant, secret).
46. **The merchant and the bands as data** (`tuning.json` → `merchant`, `bands`; `07` §2.7, `08`'s R table): every `merchant.stock` line names an item and stocks at least one; `merchant.beforeFinalBoss.itemId` is one of the stock lines (the four Torches, D-099); every floor with `merchant: true` has at least one item tagged `merchant.safeItems.tag` (`safe-item`) and `zone:<its zone>`; `bands.floors` tile the global floors from 1 with R climbing and the grades in ladder order; `bands.chestBandCap` is a grade.
47. **An encounter stays in its monsters' zone** (`06` §3): its `floorBand` lies inside one zone of its dungeon, every monster of that dungeon in its composition belongs to that zone, and each one's `levelBand` covers the band level of every floor in the band (plus a hunter's `levelOffset`).
48. **Behaviour keeps its weights alive** (Phase 7's fix): `behavior.rules` are read by the gambit parser (`sim/src/ai.ts`); a line it can read is a gambit (`self hp < 50%`, `round = 1`, `enemy status web and enemy not status grab` …), a line it cannot is a note it drops — a **warning**. A monster with two or more weighted attacks fails when an unconditional line (`{"if": "always", …}`) names one of its moves: that line wins every turn and the `aiWeight`s never roll.
49. **Curios and traps** (`07` §2.4–§2.5): a trap's `placement.templateIds` are templates of its zone that host one of its `placement.roomKinds`, and some template of its zone may host it; its `condition.partyClassIds` are classes; the monster a curio or trap calls (`curio-fight`, `ambush-encounter`, `lantern-gutters`, `smash-urns`) exists, is no boss and belongs to the curio's or trap's zone; a zone's `joiners` are monsters of that zone, neither bosses nor hunters.

**Boss arenas and telegraphs** (Phase 7, pass C2, `tools/lint/rules-c2.ts`)
50. **A boss's phase fields**: a phase's `opener` is one of that phase's attacks; its light steps, run from the boss floor's `lightAtArena`, keep the arena inside 0–100; a phase's `tide` fits the arena's top step; phase `hooks` are custom lines; phase names do not repeat.
51. **The arena's rules**: every `kind` is one `sim/src/arena.ts` runs and carries only that kind's fields (the list below); a rule's `phases` exist; its `tell` is one of `arena.tells` (a tell no rule names warns) and a clocked rule with a tell fires every 2 rounds or more; its `attack`/`attacks` are the boss's; its `adds` and `monsters` resolve; a `heel` or `hunters` monster is a hunter of the boss's dungeon, and `hunters` names one round per hunter; a `flank` names adds the boss brings; light steps stay inside 0–100, a throne lights 1–8 braziers, the tide's `wadeAt`/`chainAt`/`deepAt` lie inside its steps and a sluice wheel names its minimum; an `addAt` has its `atHpPercent`, a `reenter` a clock or an `afterRounds`, a `call` its attack.
52. **A boss's parts**: ids unique, `fromPhase` a phase the boss has, the effect's attacks the boss's own and its `removeStatuses` statuses those attacks apply; `stopTide` needs a tide or a pull to stop.
53. **Telegraphs** (`06` §8.10, D-099): a boss's attack with a `tell` carries its `hint` (any other monster's only warns); a hint is two words (a warning); an `aim` is on a single-target attack; every boss phase rolls at least one attack with an `aiWeight` above 0.
54. **The arena's room**: `boss.arena.room` is a live template of the boss's dungeon that hosts a boss (warns while the template is still `.json.later`); the floor that holds the boss sets its `lightAtArena`.

**Pacts, contracts and pets** (Phase 7, `tools/lint/rules-d.ts`)
55. **Pacts** (`07` §6.2): every `ruleFlags` entry is one the sim implements (`sim/src/pacts.ts` `PACT_RULE_FLAGS`: `loud-boots`, `every-door-locked`, `no-minimap`, `no-scouting`, `no-cartography`, `no-retreat`, `wipe-loses-waystone`, `twin-hunter`), so a typo fails instead of doing nothing; a Pact that moves the hunter (a `knobs.hunterClock` or the `twin-hunter` flag) says `needsHunter: true` and one that says it does one of them ("No hunter, no hunter Pact": the Waystone greys it out for a zone with no hunter clock); a Pact takes revives away with `revivesPerFloorDelta`, never a fixed `revivesPerFloor` that would ignore the preset; `tuning.json` → `pacts.oathTiers` climb. A hunter Pact on a dungeon with no hunter clock anywhere **warns**.
56. **Contracts** (`07` §7): the target fits the kind — `kill` and `noWipe` need a `count` and count a `familyId`, a `monsterId`, `monsterIds` or the `zone-hunter` condition; `clear` names a `zoneId`, `floor` or `dungeonId`; `light` a `lightMin` or `lightMax` and where the light is read (`at-stairs`, `chests-opened-one-floor`); `collect` a `goldR`, or a `count` with `parts-sold-one-delve`; a `condition` is one the sim checks (`sim/src/contracts.ts` `CONTRACT_CONDITIONS`) on the kind it belongs to, with the fields it reads (`no-curio-opened` a `curioId`, `tide-below-step-4` a `monsterId`, `chests-opened-one-floor` a `count`); every `monsterIds` entry is a monster and a `curioId` a curio of the target dungeon; a weekly has a `band`; every contract pays something and no contract pays more keys of a kind than the week's cap (`contracts.keyCapPerWeek`: 3 Standard, 1 Grand); once any contract exists there are at least `contracts.dailies` dailies and one weekly.
57. **Pet traits grow by use** (`03` §9): every species' `trait.growsBy` has a source in `tuning.json` → `pets.traitGrowth.sources`, each source is one the sim counts (`finds`, `hitsTaken`, `hitsLanded`, `actions`) with a weight; `usesForRank` starts at 0 and climbs; `effectPercentPerRank` ≥ 0.

**Statuses, species, elite affixes, the runner and the threat** (Phase 7, `tools/lint/rules-f.ts`)
60. **Statuses** (`03` §3.4–§3.5): each element owns one status as its mark (an upgrade such as Chill → Freeze shares its element); `upgradesTo` and `bossBecomes` never name the status itself, an upgrade never cycles back and keeps the element, a status bosses are immune to has `bossBecomes: null`, and no status becomes one bosses are immune to; a lasting status (a duration, or an `endsWhen` that is not "instant…") lists a `cleansedBy` tag — a buff, HoT or state lists `strip`, a debuff, DoT, control or mark a real cleanse; only `control` statuses carry a negative `appliesEnergyDelta` or a `skipsActionChance`; `stacking: "stack"` holds 2 or more; every status has its own `visual.icon`.
61. **Species** (`05`): trait ids are unique across the species; `body` offers at least three skin tones and three face presets (`05` §5); every species can wear every worn piece of every class's starter kit — `starterKit` and any other `…starterKit…` list — under its `restrictions` (the species half of `sim/src/armory.ts` `wearBlocker`), since a new hero is handed the kit as it is.
62. **Elite affixes** (`06` §2): every affix carries the same `hpMultiplier`, `goldMultiplier` and `xpClassBonus` (one champion rule; `monsters.ts` takes the highest of a champion's affixes, so a stray value would change every champion that rolls it); the pool holds an offensive, a defensive and a control affix; a `tell` is a short cue (60 characters at most); an affix no monster's `elitePool` lists **warns** (no champion rolls it).
63. **The balance runner's data** (`tuning.json` → `runner`, read by `tools/balance/run.ts`): `seeds` ≥ 1 and `commandCap` ≥ 100; `policy` is a scripted player and `careful.turnBackFrom` a threat band; every `[low, high]` band under `targets` is ordered and `classDamageSpreadMax` ≥ 1; `expectedFloors` names real dungeons and none holds more floors than expected; `targets.goldPerFloor.<dungeon>` lists exactly the expected floors; each recipe's id is unique, its party has 1–4 heroes of real classes (and real species when given), its `gear` is a grade or null, its `petStance` a stance or null, its level inside 1–cap, its `clearTarget` null or `[low, high]` in 0–100, its `floors` (when given) inside its zone (D-083: the Vault judged as F7 and as a start on F8); a recipe for a zone the dungeon does not have yet **warns** (the runner skips it); `bossKills` is `first` or `repeat`; each part of each `plans.<name>` names recipe sets that exist, real death rules, presets and scripted players, and at least one seed.
64. **Danger you can read** (D-092; `tuning.json` → `dungeon.threat` and each dungeon's floors): `easyAtOrBelow` < 0 < `dangerousFrom` ≤ `deadlyFrom`, so a fight at the party's own level reads Even; the champion, boss and hunter bonuses are not negative; a dungeon's `monsterLevel` never falls from one floor to the next; and going too far is deadly by construction — each zone's first floor stands at least `deadlyFrom` levels above the previous zone's first floor, so a party at one zone's entry level reads the next zone Deadly; and the party-size rows (`dungeon.partyScaling`: count, HP, damage, and D-128's boss row) hold one positive number for each party size 1–4.

Rules 11, 14, 19, 22, 23 and 27 are implemented as far as the content can be checked (`tools/lint/rules.ts` says in each what it reads); rule 27's `partChance`/`itemChance` band comparison is written since Phase 7.

**The Phase 2 fixture set.** `sim/test/fixtures/content/` mirrors this layout with test content (one class, two species, seven Cellars monsters, one zone); `sim/test/fixtures/assemble.ts` merges it with the real schemas, statuses and `tuning.json` into a temporary root that `lintCorpus(root, { skipRules: [4, 10, 14] })` and the sim's loader both read. It is not shipped; Phase 3 promoted its records into `content/` (D-068) and keeps it as the sim's small, stable test corpus.

**Gating (D-049).** The rules that demand a *complete* set — rule 3 (all 27 statuses), rule 9 (all eight field skills), rule 14's "exactly 12 elite affixes" and rule 18's "the 12 launch Pacts" — apply only once at least one file of that kind exists; an empty kind is a Phase 1 state, not an error. Every other rule applies to whatever files exist, and a dangling reference always fails, even when the referenced kind has no files yet.

## `npm run lint`

`tools/lint/index.ts`, run by Node 24 directly (`npm run lint` = `node tools/lint/index.ts`; Node strips the types, no build step, no `tsx`), exit code is the result. `npm run lint -- --saves [path]` also lints hero save records: `content/saves/*.json`, or the file or folder given. The pure core is `lintCorpus(rootDir)` in `tools/lint/lint.ts`, which the tests run on temporary copies of `content/`.

1. Loads `content/schemas/*.schema.json` into **ajv 2020-12** (`Ajv2020` from `ajv/dist/2020`) with `strict: true`, `allErrors: true`, `allowUnionTypes: false` and `strictRequired: false` — the last because ajv evaluates `allOf`/`if`/`then` before `properties` and so cannot see a parent's property list from inside a `then`; every other strict check (unknown keywords, union types, tuple shape, number formats, missing `type` beside an applicator) is on. No `format` keyword is used, so `ajv-formats` is not needed; if one is added, add `ajv-formats` and register it here.
2. Checks each schema's `$id` is `https://gloamvault.dev/schemas/<file>` and `$schema` is draft 2020-12; `addSchema` for all of them **first**, then `compile` each — cross-file `$ref`s (`hero` → `item`, `pet`; everything → `common`) resolve lazily, so compile order must not matter.
3. Validates every content file against its kind's schema (the kind is the folder: `skills/<class>/` and `items/<kind>/` are still `skill` and `item`; `dungeons/<dungeon>/dungeon.json` is `dungeon` and `dungeons/<dungeon>/templates/*.json` are `dungeon.schema.json#/$defs/template`; `content/tuning.json` is `tuning`) and every `content/examples/<kind>[-variant].example.json` likewise, matching the longest schema name the file name starts with (`elite-affix`, `item-set`, `loot-table`, `tuning` are kinds; `monster-boss` is a variant of `monster`). A schema with no example is an error (`common` excepted: nothing validates against it directly). `content/saves/*.json` validate against `hero.schema.json` only with `--saves`.
4. Runs the cross-reference and arithmetic rules above over the whole corpus.
5. Prints one line per file (`ok`/`FAIL`) and each ajv error as `<instancePath> <message> <params>`; a cross-file failure prints as `<file>: <rule number>. <what failed>` (a failure with no file to blame, such as a missing status, names the kind's folder, `content/statuses`); rule 7's techniques-per-dungeon check prints as `warning <file>: 7. …` and never fails the run; ends with `ALL GOOD: N schemas, M files` or `K failure(s)` and **exits 0 only when every file passed**. No file is written. CI runs it on every push; the sim never validates at runtime — it trusts a linted corpus and refuses to start on a `saveVersion` mismatch.

The reference implementation of steps 1–3 is the validator used to check this folder: load schemas, register all, compile all, validate every example, exit code. It ran clean on rev. 2 (17 schemas compiled, 18 examples valid; 18 and 19 since `tuning`) and rejected 113 deliberately broken variants (a passive with a weight, an Ultimate at Tier I, a weapon with no weapon type, a boss without a boss block, a hunter without `levelOffset`, a reward of kind `key`, a Luck XP line, a four-piece armor set, a grade-shape line above 100, …).

## Representation choices

Where the owning doc is silent, the schemas take the simplest reading. Each is a **Proposed** decision for James; change the schema and the example together.

- **Class `role` is a free one-line string**, not an enum: the rulebook never names a closed set of party roles. The monster `role` enum is the taxonomy of §11.1 and is closed.
- **Field skills, pet actives and monster-only skills are skill records** with `classId` one of the literals `"field"` / `"pet"` / `"monster"`, `school` the same literal, `tier: 1` and `prerequisiteId: null`, filed under `content/skills/field/`, `pet/`, `monster/`. The literals are ordinary ids, so no class may be named `field`, `pet` or `monster`. The 45-per-class count ignores all three.
- **`school` on a skill is the school's id** from its class's `schools[]`; the linter joins them.
- **`rankScaling` is signed**: `effectPerRank: 4`, `costPerRank: -2` (§5.2's +4% / −2%), so the sim adds without knowing the sign.
- **Ultimates** carry `cost: 0`; the 100-Momentum price is a rule of `isUltimate`, not a field.
- **Skill `requirements`** (`shield`, `weaponTypes`, `dualWield`, `twoHanded`) is optional and only present when a skill needs something in hand (Shield Slam, Iron Dance, Executioner).
- **Skill `tags` are a closed enum** (aoe, singleTarget, control, mobility, momentum, light, scouting, heal, cleanse, buff, debuff, dot, shield, taunt, reach, summon, revive, utility, field) so the Skill Hall's "Recommended loadout" can rely on them; extend the enum in `skill.schema.json` when a new tag is needed.
- **Monster techniques are a list on both ends**: `class.monsterTechniqueIds` (skill ids) and `monster.monsterTechniqueSkillIds` (the same skill ids, from the monster's side), because one monster teaches up to two classes (`06` §3 "Technique:" lines) and rule 7 lints the pair. **Phase 7:** the skill may name the moves that teach it (`monsterTechniqueMoveIds`, the monster's attack ids — Wraith-step only from the Wraith's Drift, the Lament only from its Wail; absent means any of its moves), and a technique whose monster lives in a dungeon not yet written carries `monsterTechniqueLater` instead (the Mender's Troll's Regrowth, `warren-troll`) and cannot be learned. One table in `tools/content/gen-class-lib.ts` (`TECHNIQUES`) writes these fields for all six class generators.
- **A Skill Tome is one item def plus the skill on the instance** (Phase 7): `items/tome/skill-tome.json` (hand-kept; the items generator leaves `tome/` alone) and `ItemInstance.skillId`, so every skill has its Tome without a file per skill; its value for selling is the Skill Hall's price of its tier (`skills.tomes.valueR`), not the def's `value`.
- **A class may offer more than one starter kit** (D-099): `starterKitName` names the default kit and `starterKitOptions[]` holds the others (`id`, `name`, `description`, `starterKit`, `starterSkillIds`) — the Warden's spear, the Blade's greatsword. New hero offers them; a wayfarer arrives with the default kit.
- **`weaponType` keeps the generic `bow`** for class lists and adds `longbow`/`shortbow` for items and species locks (`05`: "Longbows locked, shortbows and crossbows fine"); `shortSpear` is the 1h spear, `spear` the 2h reach spear; `lantern` and `horn` are the Beast Tamer's off-hands.
- **`materialRung` is the ladder index 0–8**, redundant with `grade` on purpose: it is the field the blacksmith's promotion reads, and the linter checks the two agree. Regional variants (Steel/Bluesteel) are the material item's own `name`; the ladder has nine rungs, not eighteen.
- **An item file carries instance-shaped fields** (`durability`, `plusN`, `itemLevel`, `affixes` …) as its starting values, so a shop item, a starter-kit piece and a pre-rolled drop are all plain item files. A hero's copy is `item.schema.json#/$defs/itemInstance`: the item id plus only what use and care change.
- **Sets are their own record** (`item-set.schema.json`): the pieces are ordinary items with `setId`; `bonuses` holds `"2"` and `"4"` effect lists (a `ringPair` only `"2"`), `bonusText` the card lines, because `08` §6's bonuses do not ride the ladder and so cannot live on a piece.
- **Pet grade lives on `petInstance`**, not the species; the species carries a `gradeBand` and lists actives in unlock order; a hatched pet uses the first N by grade (rule 28). The stamina cost of an active is the pet skill's `cost`.
- **`petInstance.name`** (the player's name for it) and **`stance`** are stored on the instance; §9 makes the stance the pet's whole control surface, so it belongs in the save.
- **A floor carries `encounterTableIds`**, several tables drawn with equal weight (`07` §2.3: "Cellars A, B; Cellars C"); an encounter carries one `tableId`. §11.1 speaks of "encounter tables per floor band" without saying how a table is keyed.
- **Elite affixes are records** (`elite-affix.schema.json`, `06` §2's twelve) with an `affixClass` for the composition rule, the champion's multipliers (`hpMultiplier` 2.5, `goldMultiplier` 3, `xpClassBonus` 2) and a `floorMin` for the F1–2 teaching pool; monsters list the ones they may roll in `elitePool` and rule 14 resolves them.
- **Monster `rows`** is an array of `front`/`back` (which rows it may stand in); the common `row` enum's `either` is for targets, not placement. A monster's `ambushModifier` is its individual surprise modifier (`06` §8.3); the encounter's is the family's.
- **Monster `statusImmune`** is separate from `immune` (damage types) because the rulebook treats elements and statuses as different tables; a boss's `boss.immunities` is the `06` §7 list on top.
- **Boss drops are two reward lists**: `everyKill` (the stack, the grade-rolled item, stones, the God item as a `chance` line per `difficultyMin`) and `firstKill` (the Relic, the Tome, keys as items, `title`, `waystone`, `luck`). `06` owns phases, attacks and first-kill drops; `08` §11 owns the per-kill rows; where they still differ the example follows `06` and the loot table's `bossFirstKill` only names the monster.
- **Boss `cannotFlee: true`** is stored even though §12.1 makes it universal, so the sim reads one field for bosses and hunters alike.
- **Hunter `levelOffset`** (default 3, `06`: level = floor + 3) and **`roomsPerTick`** (a decimal: 0.5 = one room every 2 ticks; the sim keeps ticks-per-room internally) are on the hunter block. `07` §2.9's "+2 levels" is the open question on `06`; the field takes either.
- **Behavior lines and hero `aiRule`** are strings in the gambit language of §3.6 (`IF … THEN …; ELSE …`); the parser owns the grammar. The linter only checks that a `then` naming an attack resolves.
- **A zone has `bossIds[]` and a nullable `hunterId`** so the Drowned Vault carries Sister Naesa on F7 and the Hollow King on F8 (D-104); a floor still names its one `bossId`, its `lightAtArena`, and `hunterClock: null` on boss floors. A zone whose floors all carry a boss keeps its hunter id with no clock anywhere (the Vault Leech, met only at the Leech Jar and in the King's last phase, `07` §2.9). A zone with `waystone` has its Waystone in the entry room of its first floor (`07` §1.1: F1, F4, F7; `sim/src/town.ts` `litWaystones`, `waystoneFloors`). A zone's optional **`joiners`** are rare monsters that join any of its encounter fights at a chance (`06` §3.3: the Pearl Ooze, 5%; `sim/src/explore.ts` `spawnEncounter`).
- **A curio outcome may carry `also[]`** (Phase 7): more effect lines resolved after its `effect`, in order (`07` §2.4's "0.06 R and the floor's hunter clock +10"), so a two-part outcome needs no composite hook. A curio's `requires` item may be a material or a part the delve carries (a Cloth unit, a Brine Pearl), counted from the delve's materials when no bag holds it.
- **Traps may carry `placement`** (`templateIds`, `roomKinds`: "the midline of cry_t_catacomb_run", "picking up the room's treasure") and a **`condition`** (`lightBelow`: the Drowning Bell rings only in Shadowy light or darker; `partyClassIds`: the Warding Glyph waits for a caster). **When an unrevealed trap fires** (`07` §2.5, `sim/src/delve.ts` `springTraps`; Phase 7): `enter` on entering the room; `step` when the party crosses it (leaves by a door or the stairs); `open` on the door it blocks, else on the stairs or on opening a chest or curio in its room; `loot` on taking the room's gold or opening its chest; `time` on entering when it reads the light, else on opening a chest or curio there. Only a **revealed** trap shuts its door; an unrevealed one fires when the door is opened and the party goes on. A trap line with no `target` lands on the victim — the lowest-Perception hero — alone; `partyFront`/`partyBack` are the heroes' rows (out of combat, the row each class stands in: `tuning.json` → `floors.frontRowClasses`).
- **A secret's chest may be locked** (`chestLocked`, `07` §2.6 the Pearl Cache). A blessing's Shield line with a `percent` is a share of each hero's own max HP.
- **Gravehollow's floors' own numbers** live in `tuning.json` → `floors` (a room's trap chance, a gauntlet's traps, one Monster room per floor, the Funeral Urns' per-urn odds, the row each class stands in), **Dunmore Quist's cart** in `merchant` (the stock lines in town R before his markup, the four Torches before a final boss, the zone's two safe items by tag, gear, the stone chance, his lamp) and **08's R table** in `bands` (the global floors of each band, its grade and R; the chest band's cap) — `sim/src/grades.ts` keeps a pinned copy only for the town helpers that take no tuning yet.
- **Curio choices carry `requires[]`** (`common.requirement`): a consumed Torch, "Foraging rank 3+", "Detection ≥ 14", "Strength ≥ 14", "Lockpicking vs 12", a 0.05 R stake, a class in the party. `safeItemId` stays on the curio as the item that makes the good outcome certain; the choice that needs only that item is the purchase. Outcomes with an empty list mean "nothing happens" (the Leave choice).
- **Traps carry `trigger`** (`enter · step · open · loot · time`) with the designer's exact `triggerNote`, **`revealedBy`** (`detection`, plus an always-reveal `classId`, `petId`, `fieldSkillRank` or `criticalScout`), **`effects[]`** in order, and **`disarmReward[]`** as reward lines, so "2 Rawhide, 0.01 R" is two lines; field-skill XP for the disarm is a rule, not data.
- **Room templates** use cardinal door sides with a cell offset, a `[x, y, z]` camera with a vertical FOV, props flagged `lightSource` for the braziers of §4.2, and the `07` §2.2 budgets (`triBudget`, `drawCallBudget`); the `11` art file's figures are the owner if they differ.
- **Difficulty knobs** are every row of `07` §6.1 (`enemyHpPercent` … `finalBossExtraShards`), all optional inside a Pact and a preset; absent means Normal. The three launch presets are required on every dungeon; a Pact adds `weight` (its Oath contribution), `ruleFlags` for what no knob can say and `needsHunter`. Phase 7 added the knobs the Pacts need: `wearPercent` (Brittle 150), `revivesPerFloorDelta` (Thin Line −2), `ambushBonusPercent` (Loud Boots 15), `lightPerNewRoom` (Long Night −8) and `lockedChestPercent` (Every Door Locked 30). **How a Pact meets the preset** (`sim/src/pacts.ts` `combineKnobs`): a percent knob multiplies (Pack Hunters on Hard: 110 × 125% = 138), a bonus knob adds (`eliteAffixBonus`, `trapDifficultyBonus`, `revivesPerFloorDelta`, `ambushBonusPercent`, the chest and boss extras), every other knob replaces (every Pact is harsher than every preset on the knob it moves).
- **Contracts** (`contract.schema.json`) are templates the board fills with the band: `kind` + `target` for the condition, `reward` in R plus `keys[]` (standard/grand), an optional `chestId`, and `items[]` for Torches or a Skeleton Key. The weekly key caps are a rule (lint rule 56; `contracts.keyCapPerWeek`). Phase 7 added `target.monsterIds` (several monsters counted together: the Cellars' vermin, the Grinning Company) and `target.curioId` (the curio `no-curio-opened` watches). The board itself, its progress and its claims live on the profile (`sim/src/contracts.ts`), not in content.
- **Loot tables** (`loot-table.schema.json`) are one record per floor band and dungeon: `gradeShape` is the drop shape of §6.2 — **centre 56 · one below 25 · one above 14 · two above 4 · three above 1**, summing to 100 — with a missing lower grade folded into the centre (the Cellars: F 81 · E 14 · D 4 · C 1); `treasureRoom` holds `07` §2.7's chest, lock and trap odds; `bossFirstKill` points at the boss monster.
- **Chest odds**: the rulebook's Standard Gear Chest at band B reads **B 56 · A 25 · S 14 · SS 5 · God 0**, which sums to 100 and is what the example carries; Grand shifts one grade up and adds the 5% Divine Shard line. `08` §10.1's fold rule (a God point moves to SS) is the same table written from the +4 line.
- **`tomeTiers`** on a chest is the tier range in a Skill Tome bag (Standard I–III, Grand II–IV) and null on other chests.
- **Status records carry their magnitude** as `magnitudeOf` (`hitDamage · maxHp · attack · fixed`) + `percent`, written from the §3.5 table: Bleed is 25% of the applying hit per turn, 3 turns, 3 stacks; Poison 3% of max HP; Regen's X is `fixed` by the skill. `kind` adds `mark` (Mark, Smite, Wither) and `state` (Veil); `element` names the element whose hits apply it; `endsWhen` carries an until-condition (Grab, Veil) with `durationDefault: null`; `bossBecomes` is `06` §7's Stun → Daze / Freeze → Chill. `upgradesTo` (Chill → Freeze), `skipsActionChance` (Fear, Stun) and a `visual` block are there because §3.4–§3.5 state them and nothing else owns them.
- **Species rules are typed knobs** (`species.schema.json#/$defs/rule`), one object per trait, covering every "Exact rule" and "Cons" line of `05`: `speedBase`, `hpMultiplier`, `manaMultiplier`, `xpMultiplier`, `carryMultiplier`, `dodgeBonus`/`dodgeCap`, `fortuneBonus`, `detectionBonus`, `lightBandShift`, `armorPenaltyMultiplier` per family, `shopPriceMultiplier`, `promotionCostMultiplier`, `ambushModifier`, `immunities[]` (statuses), `forcedRowMoveImmune`, `resist{}`/`weak{}` by damage type, `statusResist{}`, `enemyAccuracyBySize{}`, `fieldSkillBonus{}`, `fieldSkillStartRank`, `loadoutPresets`, `innateSkillId`, `naturalArmorBase` and the Orc's and Halfling's one-offs. A species' con line is a trait too, so the card can print it.
- **Species restrictions** are one of three shapes by `kind` (`weaponType`, `slot`, `shieldType` with `buckler · kite · tower · all`), each with an optional `reason` for the card.
- **The hero keeps `loadoutPresets`** (named saved loadouts, ≤ 4; rule 29 applies the species count), **`naturalArmor`** (the Draconid's Scales: `defense`, `itemLevel`, `xp`, `affinities`; null otherwise) and **`freePointsSpent`** (the six creation points).
- **Luck is never trainable** at the schema level: `skill.xpTags` and `hero.attributeXp` use `trainableAttribute`, the seven without Luck; a boss's `luck` reward is the one way it moves after creation.
- **Gold on the hero** is the delve's unbanked stake only; banked gold is a profile field the hero schema does not own.
- **`tuningNumber`** (`common`) is the shape of `content/tuning.json`, the balance runner's tables; no content schema uses it.

## Wayfarers (D-091) and lint rule 34

- `content/wayfarers/<id>.json` (schema `wayfarer.schema.json`): the Wayfarer Chest's cast, owned by `docs/04-CLASSES.md` §7 and written by `node tools/content/gen-wayfarers.ts` (edit the table, never the JSON). A chest of kind `wayfarer` (`chests/standard-wayfarer-chest.json`) has `dupeRule: "none"`, no sub-types, no Tome tiers and no Divine Shard.
- **Rule 34:** each wayfarer's species and class exist; its three starter skills are Tier I skills of its class, not an Ultimate, at least one active and at most two passives; its creation points add up to 6 + 1 per grade above D; names are unique across the cast; every grade a wayfarer chest's table gives a chance to has at least one wayfarer; and a wayfarer's `look` (Phase 5, `common.schema.json#/$defs/heroLook`: frame, skin, face, hair) names a skin tone and a face preset its species has (`skin` < `body.skinTones.length`, `face` < `body.facePresets`).

## Items as built in Phase 7 (pass B) and lint rules 40–44

- **Optional item fields** (`item.schema.json`): `tags` — `safe-item` with `zone:<zone id>` on the merchant's safe items (`07` §2.7: he stocks two of the zone's), `boss-only` on a boss's own relic (never a random drop or a chest's), `chest-key:standard` / `chest-key:grand` on the keys the Curio Merchant takes (`07` §7), `skeleton-key` on the keys that open a locked chest or door, `regional` on a material that is a regional name of its rung; `uniquePower.attributes` — a named unique's attribute lines; `active.text`, `active.instant`, `active.usesPerFloor`, `active.timing` (`fight` · `afterFight`) — a relic's card line and how it is used; `consumable.text` — what a safe item answers. A chest may carry `minBand` (the Grand Wayfarer Chest: from band E). A wayfarer may be grade S.
- **Chest keys are counted, not carried**: a key reward or a contract key adds one to `profile.materials[<key id>]` (`chests.ts chestKeyItemId(content, tier)` names it); `town.ts openChestWithKey` spends one on a chest of its tier.
- **Rule 40:** an egg item is `<pet id>-egg` of a pet that exists, carried (slot null); once eggs exist, every pet species has one.
- **Rule 41:** a key carries exactly one of `skeleton-key` or `chest-key:<tier>` (a tier some chest has), one chest key per tier, no consumable, active or ammo block; every key tier a contract pays has its key. Gated (D-049): it applies once some key carries such a tag.
- **Rule 42:** a consumable has its consumable block and ammo its ammo block (no other kind carries one); a consumable usable in a fight does something; a loot table's consumable drops are consumables, ammo or treats; a starter kit's stack fits; a `safe-item` is a consumable naming exactly one zone, and every `zone:` tag names a zone of a dungeon.
- **Rule 43:** a set has a piece of every armor slot at each grade it drops at, and every piece below the top grade written has a next-grade piece in the same set and slot (`08` §6: membership survives promotion); a named unique (not God) is B or above, carries its signature and is no set piece.
- **Rule 44:** an instant or after-fight relic has no action weight and any other an Item action's (`combat.weights.item`); a `boss-only` item is named by some boss reward line (a warning until the boss is written); `regional` marks a ladder material, and a rung never has only regional names.

## Boss arenas (Phase 7, pass C2) and lint rules 50–54

`07` §2.8 owns each arena (the room, the arena rule, add timing, the tells, the light); `06` §3 the boss (phases, attacks, drops). Both live in the boss's monster file and run in `sim/src/arena.ts`, called by the fight at the start, at each turn's start and end, at each new round, after a monster's attack and for the heroes' Arena and Torch actions.

- **Attacks**: `tell` (a sentence) makes an attack telegraphed — every monster, not only bosses: the tell shows on its turn (a normal weight, tuning `arena.tell.windupWeight`) and the blow lands on its next unless a status of `arena.tell.breakers` (Daze, Silence, Stun, Freeze, Petrify) lands on it first. `hint` is the tell's two words (D-099; the attack's name stands in). `aim` picks a single-target attack's hero: `lowestHp`, `mostMomentum`, `lowestStrength`, `marked`, `markedOrChilled`, `backRow`, `fullestPool`, `caster`, `mostGold` (not yet read).
- **Phases** (`boss.phases[]`, all optional beside `atHpPercent`, `attacks`, `adds`, `arenaRule`): `name`; `light` `{ set }` or `{ add }` when the phase begins; `speed`; `row`; `size`; `opener` (the boss's first move of the phase); `tide` (the water jumps to at least this step); `statusImmune`; `hooks` (custom lines installed on the boss). A phase's attacks with their weights roll; phases differing in weight carry their own copies of an attack (`toll` / `toll-2`).
- **`boss.arena`**: `room` (the template), `tells` (`{ id, hint, cue }`, `07` §2.8's table), `rules` — each `{ kind, phases?, … }` with only its kind's fields:
  - `lightsOut` `every`, `amount`, `tell`, `params.requiresCrew` — a light step on a clock (Vexa's lanterns).
  - `flank` `bands`, `monsters`, `params.accuracy` — those adds reach the back row in those light bands, at +accuracy.
  - `barricade` `count` kegs of `hits`, `status`/`duration` for the slick floor, `params.endsWithAttack` — the boss's back row is out of non-reach melee while it stands.
  - `reenter` `every` + `tell` (waves) or `afterRounds` (each add), `params.groups` (`start`, `phase-2`, …) — fallen adds come back, each once.
  - `frenzy` `attacks` dropped, `params.belowHpPercent`, `params.actions` per turn.
  - `oath` `status`, `duration`, `params.tauntClass` — the boss strikes only heroes who struck it.
  - `candles` `count`, `tell`, `adds` behind the doors, `params.doorsAt` (candles out), `params.doorsAtPhase`.
  - `piles` `count` of `hits`, `damageTypes` that burn one.
  - `call` `attack`, `adds`, `params.fromPiles`, `params.refill` (top up to the listed count, never past), `params.hpPercent`, `params.grab: lowestStrength`, `params.group`.
  - `heel` `monsters` (hunters), `params.hpPercent` (current HP), `params.row` — at the start, unless killed this delve.
  - `tide` `max`, `every`, `fastEvery`, `fastBelowHpPercent`, `tell`, `status`/`duration` (the wade), `attribute`/`min` (the sluice wheel), `adds` (the deep), `params.wadeAt`, `chainAt`, `chainPercent`, `deepAt`.
  - `outOfReach` — the boss is out of non-reach melee in its phases.
  - `braziers` `count`, `amount` (a Torch's worth unless the delve's `torchValue` says otherwise).
  - `lightBand` `bands`, `attacks`, `params.reachBackRow`, `critBonus`, `shadowPercent`, `addsStatus`.
  - `pull` `every`, `fastEvery`, `fastFromPhase`, `tell`, `params.frontStatus`, `frontDuration`, `backStatus`, `backDuration`, `bladeAttack` (comma-joined ids), `bladePercent`.
  - `pulse` `every`, `tell`, `status`, `duration` — on every caster.
  - `addAt` `atHpPercent`, `adds`, `params.missingOnly`, `group`, `cause`, `name`, `hp`.
  - `hunters` `rounds` into the phase, `monsters`, `tell` — never one killed this delve (`DelveState.huntersKilled`).
  - No arena rule may lock a party out: the barricade and `outOfReach` bind melee only while someone in the party can reach past.
- **`boss.parts`** (≤ 4): `{ id, name, hpPercent, damageTypes, crit, fromPhase?, effect }`; one blow of at least `hpPercent` of max HP, of one of the types (any when empty), a crit when `crit`, breaks it once; `effect` is `removeAttacks`, `attackMultiplier`, `removeStatuses`, `stopLight`, `stopTide` and/or `line`. The monster's `parts.breakLimb` stays the single-limb rule of every other monster.
- **The fight log**: `{ kind: 'arena', data: { what, boss, … } }` with `what` one of `phase` (`phase`, `phases`, `name`, `speed`), `light` (`from`, `to`, `band`, `cause`: arena · phase · lantern · torch · brazier; `lanternsOut`), `tide` (`from`, `to`, `cause`: rise · phase · sluice), `brazier` (`index`, `lit`, `of`, `light`), `recall` (`cause`, `monsters`, `count`), `hunterReturns` (`hunter`, `wave`, `skipped`), `partBreak` (`part`, `name`), `candle` (`out`, `of`), `doors`, `barricade`, `keg`, `pile`, `sluice`, `slick`, `pull`, `pulse`, `oath`, `frenzy`; and `{ kind: 'tell', data: { hint, cue, source: arena · attack, ref, first, boss } }`; `tellBroken` when a blow is broken off. `DelveState.stats.bossArenas` keeps one row per boss fight.
- **Tuning** `arena`: the wind-up's weight and breakers, re-entering adds' HP, the returning hunters' level offset and HP, the heroes' arena habits on auto (`torchBelowLight`, `brazierBelowLight`, `sluiceFromTide`, `swapOnPull`).
- **Rewards**: `everyKill` on every kill, `firstKill` on top when `DelveOptions.bossKills` has none for the boss; a reward line's `difficultyMin` is honoured; chest keys and `shard` lines count in materials; `title`, `luck` and `waystone` lines wait in `DelveState.bossRewards` for `settleDelve`, which gives the title and the Luck to the heroes standing.
